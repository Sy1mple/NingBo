# 状态检测归属

检测结果的判断维护在设备所属场景的 `jetson/diagnostics.py`：

| 模块 | 设备及检查内容 |
| --- | --- |
| experiments/environment | DHT11 温湿度范围、BH1750 光照有效性 |
| experiments/smoke | 串口在线、FFAA 帧、浓度有效性 |
| experiments/body_temperature | 驱动配置、体温有效范围 |
| experiments/ultrasonic | 测距范围、蜂鸣器输出极性 |
| experiments/servo | 硬件 PWM 配置、往返控制线程 |
| experiments/stepper | 相序控制线程及电气反馈 |
| experiments/fan | 风扇输出极性 |
| experiments/access | 门锁输出极性 |
| hardware/rgb | 跨场景共用 RGB 颜色及三路输出 |
| hardware/adc | 共用 ADC 采样、电流/电压反馈及阈值 |

`hardware/diagnostics.py` 仅提供通用数值校验、控制锁、初始化保护、线程检查、GPIO 读回和结果组装。设备专有规则在上述场景中。

各设备状态结果 VP 归入其 `serial_screen/addresses.py`；共用 RGB 的 VP 在 `hardware/rgb/status_addresses.py`。
`system/diagnostics` 保留兼容入口、分组、任务调度、取消、汇总以及公共状态页桥接。
三个检测按钮及 DeviceService 接口保持兼容。环境场景的两个结果使用 GB2312 文本，其他结果沿用状态码。
状态检测只读取当前状态和反馈，不启动执行器；未初始化电机保持 unknown。

## 环境场景中文结果

| 检测项 | 文本 VP | 控件文本长度 | 编码 |
| --- | --- | --- | --- |
| DHT11 | 0x6000 | 每次写入 2 字节 | GB2312 |
| BH1750 | 0x6001 | 每次写入 2 字节 | GB2312 |

沿用用户现有串口屏地址及中文字库，传感器检测按钮为 VP `0x9001`，返回值 `0x8001`。
相邻 VP 各只能写入一个 GB2312 汉字：检测期间为“检”，协议采集及数值校验通过为“好”，失败为“坏”。
待检测为“待”、未配置为“缺”、未启用为“停”。每次只写一个 Word，不附加结束符，以免覆盖下一项。
完整的“正常/异常”各需两个 Word，不能直接用于这两个相邻地址。控件读取超过一个 Word 时，显示还可能包含下一项内容，须以实屏核对结果为准。
状态码仍用于内部报告，电压或电流不作为这两个数字传感器的判定依据。

## 原地址与文本控件的完整状态词显示

2026-10-19：地址继续固定为 `0x6000` 和 `0x6001`，控件仍为“文本显示”，文本长度保持 2 字节。
两项使用专用中文字库 `90_STATUS_GB2312_64x24.hzk`，字号 64×24，编码 0x01 GB2312。
字库把程序现有的“好”(BAC3)、“坏”(BBB5)、“检”(BCEC)分别绘制为完整状态词“正常”“异常”“检测中”。
这里每个状态词是一个宽字形，因此仍只占一个 Word，不覆盖相邻 VP。仅这两个控件使用专用字库，其他控件继续使用原字库。
字库文件已放入原屏幕工程的 FONT 和 DD_SET；下载必须包含 90 号字库，真实屏幕效果尚待下载验证。
