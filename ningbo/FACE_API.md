# 讯飞人脸 API 接入说明

当前默认人脸后端为 `xfyun`，使用讯飞**自研**「人脸比对」及「人脸检测和属性分析」，不使用 `sensetime` 版本。语音模块保持原有讯飞听写实现。

## 开通和配置

1. 在[讯飞控制台](https://console.xfyun.cn/)为本项目创建专用应用，开通自研「人脸比对」及「人脸检测和属性分析」，领取可用的免费试用包。必须是同一应用同时获得这两项授权。语音听写授权不代表已有人脸授权。
2. 确认两项能力的**剩余免费次数和到期时间**。本项目不预设平台固定赠送次数；不同版本、账户及活动的授权可能不同。不要用 `sensetime` 文档中的赠送次数配置自研接口。
3. 在 `ningbo/` 目录执行：

   ```bash
   python deploy/configure_face.py
   ```

   密钥隐藏输入，写入本机 `.env.face`。也可以按 `.env.face.example` 手动填写。使用人脸专用的 `XFYUN_FACE_APP_ID`、`XFYUN_FACE_API_KEY`、`XFYUN_FACE_API_SECRET`，不自动借用 `.env.voice`。

4. `XFYUN_FACE_DETECT_LIMIT` 和 `XFYUN_FACE_COMPARE_LIMIT` 是本机可使用的**总次数**；首次配置不要大于控制台剩余免费次数。`XFYUN_FACE_FREE_EXPIRES` 填两项免费包中较早的到期时间，须带时区（北京时间 `+08:00`）。仅当两项控制台均显示“—”、未显示日期时填 `-`，表示日期未提供，不代表永久免费；此时按本机次数上限和平台授权结果停止。缺少任意一项时不会调用接口。
5. 在 Jetson 完成部署后执行 `bash run.sh`，使用「人脸录入」`0x3010 / 0x5010` 和「身份验证」`0x3020 / 0x5020` 按钮。当前屏幕没有注册停止按钮；验证任务自行结束，程序退出仍会取消任务和关闭执行器。

仅使用免费包，不购买套餐或启用付费服务。本机计数不能读取平台实际余额，也不能识别同一应用在其他设备上的消耗，因此请使用专用应用。账户侧是否存在付费授权由控制台决定，程序无法替平台阻止扣费；本机上限和期限必须按实际免费授权填写。

## 工作方式和额度消耗

- 已接入录入按钮 `0x3010 / 0x5010`。主程序只预先建立等待页面；点击录入后才打开摄像头和尝试启动本地 Firefox。SSH 电脑通过 `camera_view.py 用户名@开发板IP` 在电脑浏览器查看开发板上的同一摄像头，两端共享单个采集线程。
- 默认先显示约 3 秒供人员对准镜头，再采集录入照片。结果会显示在网页中；成功时记录本地人员编号及姓名，完成后关闭相机并清除实时画面。网页不新增相机/门锁控制按钮。

- 摄像头照片先通过讯飞检测，只有恰好一人、尺寸足够且清晰时才进入比对。
- 每次录入保存一张合格 JPEG 和人员姓名到 `data/faces_xfyun.sqlite3`。录入前与现有人员逐一比对，已存在者不重复添加。默认自动命名，仍可用 `--enroll-name` 设置姓名、`--list-faces` 查看、`--rename-face ID NAME` 改名。
- 识别时，一张当前照片与每名已录入人员的一张照片逐一调用比对 API。库中有 N 人时，一个有效识别轮次通常消耗 **1 次检测 + N 次比对**；第一次录入空库通常只消耗 1 次检测。多人、无人或画面质量不足时仍可能消耗检测次数。
- 默认相似度至少 `0.80`，前两名差值至少 `0.05`，连续两轮确认同一人才认为成功。需要继续确认时，下一轮至少等待 3 秒，所有请求至少间隔 1.1 秒，适合少量人员的实训演示。人数增加会使识别更慢且更快消耗试用次数。
- 每次点击身份验证只执行一次任务，明确成功或失败后停止采集和调用。默认等待有效人脸的时限为 20 秒，超时或网络响应超过时限不会开锁。匹配成功时 `unlock_on_match=True`、`unlock_seconds=2.0`，门锁通电 2 秒后自动断电。失败（含不匹配、多人、空库、超时、接口错误）时不开锁，蜂鸣器响 2 秒；等待人脸和第一轮确认中不鸣响。两秒联动期间不接收新的验证任务。
- 身份验证成功亮绿灯两秒、失败亮红灯两秒，到期释放门禁 RGB 状态；停止验证或开始新录入会清除上一轮的灯色计时。
- 验证失败蜂鸣由智能门禁直接控制，鸣响两秒后关闭；录入或取消不触发验证失败蜂鸣。距离检测独立控制蜂鸣器，停止检测直接关闭蜂鸣器。
- 停止请求会使当前会话失效，迟到结果不再开锁；停止期间不会提交新的人员录入。网络请求或摄像头读取未返回时，沿用已有线程退出保护机制，禁止启动重叠任务。

## 免费额度保护

`data/face_usage.sqlite3` 按 APPID 和能力持久计数。失败、超时请求也预先计入；**重启、跨天和修改密钥不会重置同一 APPID 的计数**。达到配置上限、免费包到期、鉴权失败、网络失败或响应格式异常时，人脸任务停止并撤销开锁条件，不切换供应商或购买额度。

保留用量数据库，不要为了继续调用而删除。修改免费次数配置不会清除历史用量；重新领取免费包时仍保守沿用累计用量，须结合历史计数和控制台剩余额度核算后调整本机总上限。

## 数据和兼容性

录入照片保存在本机 SQLite 数据库中，不做云端建库；检测时上传当前照片，比对时上传当前照片与录入照片。云服务对上传数据的处理以讯飞服务条款为准。本机照片库设置仅当前用户可读写的权限（Linux `0600`）。

旧 `data/faces.sqlite3` 存的是 SFace 向量，不能还原成照片，需重新录入；新库使用不同文件名，不覆盖旧库。原 TensorRT/CPU 后端代码保留，可明确选择 `--face-backend tensorrt` 或 `opencv_cpu`，须另行提供本地模型和对应依赖；不会在云端失败后自动切换。

当前接入是照片检测和比对，未增加活体检测。与原有单目摄像头门禁一样，不能把它当成防照片攻击的实机安全认证。

## 检查与部署

```bash
python main.py --check-config
python main.py --check-acceleration
python deploy/verify_models.py
python -B -m unittest discover -s tests -v
```

配置检查不读取真实密钥或连接硬件。云端后端的加速检查显示 `skipped`，模型检查跳过云端不需要的权重，**这些通过不代表云端调用成功**。`--init-face-db` 只初始化本机照片库，不消耗 API 次数。

默认人脸和语音均为讯飞 API，部署脚本不再强制安装 TensorRT、CUDA PyTorch、Whisper 或校验本地权重；选择本地后端时才安装/校验相应组件。部署目标仍为原 Jetson Xavier NX / JetPack 5 环境，需在开发板确认依赖、权限、摄像头及网络。

离线测试模拟接口和摄像头，不上传真人照片、不消耗额度。实际授权、免费包、网络时延和识别阈值须配置后在开发板实测。

官方协议依据：

- [讯飞自研人脸比对 API](https://www.xfyun.cn/doc/face/xffaceComparisonRecg/API.html)
- [讯飞人脸检测和属性分析 API](https://www.xfyun.cn/doc/face/xf-face-detect/API.html)

两项服务都使用 `https://api.xf-yun.com/v1/private/s67c9c78c`，按 `service_kind` 区分功能；POST 请求采用 HMAC-SHA256 签名，响应须同时验证平台 `header.code` 和 Base64 解码结果中的 `ret`。
